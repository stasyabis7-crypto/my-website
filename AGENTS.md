# Инструкции для ИИ-агентов и разработчиков

Этот файл — общие правила работы с кодом проекта для любого инструмента:
Claude, другой ИИ-ассистент или человек. Не специфично для одного бренда
ассистента, применяется всегда.

## Изображения

- PNG на сайт не публикуются: `npm run images:prepare` конвертирует их в WebP
  без потери качества, сохраняет размеры/прозрачность и обновляет подключения.
- `npm run dev` делает это автоматически при добавлении файлов; тот же шаг
  обязателен перед деплоем. Не создавать отдельную реализацию конвертации.
- Не перезаписывать существующую другую картинку при совпадении имени.
  Подробности и границы импорта — `docs/images.md`.

## Структура проекта

- Данные и подборки Главной — `pages/home/`; её публичный HTML остаётся в корне.
- Материалы раздела/кейса — рядом с его `index.html` в `projects/`: `assets/`
  для баннера/обложки раздела, `covers/` для обложки кейса, `media/` для содержания.
- Повторно используемые CSS/JS — вместе в `components/<имя>/`.
  `styles/` содержит только общие основы ДС, `site/` — общие службы сайта.
- Общие SVG-иконки и их CSS — единый компонент `components/icons/`.
  Аватар, логотип и favicon — `components/site-brand/`.
  Не создавать общий корневой `assets/`: ресурсы должны лежать рядом со своим компонентом или страницей.
- Документация — `docs/`, локальные стенды — `dev/`, инструменты — `scripts/`.
- Новые имена файлов и каталогов — lowercase-kebab-case; не создавать рядом
  папки-дубликаты с пробелами, другим регистром или другим форматом картинок.
- При переносе обновлять подключения, документацию, проверки и список ресурсов
  для CDN. Публичные адреса страниц сохранять. Подробная карта — `README.md`.

## Кнопки — только из дизайн-системы

`styles/buttons.css` — единственный источник стилей для ЛЮБОЙ новой кнопки
на сайте. Правило жёсткое, без исключений:

- Все контролы имеют единую высоту `--button-height` из
  `styles/buttons.css`, включая иконку сверху, только иконку и переключатель
  `.btn-segmented` целиком (его пункты вписаны внутрь). Текст во всех
  контролах один: шрифт, размер, начертание и трекинг `.btn`.
  Варианты меняют компоновку и заливку, но не высоту.
- Новая кнопка = класс `.btn` + один `.btn--fill-pink`/`.btn--fill-white` +
  опционально один `.btn--icon-left`/`--icon-right`/`--icon-top`/`--icon-only`.
- Свой цвет, ховер, заливку или `transition` для кнопки в другом CSS-файле
  или в `<style>` конкретной страницы — не писать. Даже "только для этой
  страницы", даже "почти как в ДС, но чуть иначе".
- Нужного типа заливки/расположения иконки ещё нет — новый тип добавляется
  в `styles/buttons.css`, а не рядом с местом использования кнопки.
- Позиционирование самой кнопки (отступы, место на странице, ширина
  контейнера) — это не стиль кнопки, по-прежнему живёт в файле страницы/секции.
- `.btn` — только для кликабельных контролов-действий (`<button>`,
  `<a href>` в роли действия, `[role="button"]`). Тег/бейдж/лейбл/чип и
  любой другой некликабельный элемент — не кнопка, даже если похож формой
  (скругление, паддинги): для него свой отдельный класс, не `.btn`. И
  наоборот — если элемент кликабелен и запускает действие, это `.btn`,
  отдельный "почти как кнопка" класс под него заводить нельзя.
- Основные кнопки Главной (`.mood-primary`, `.site-header__cta`) используют
  `.btn`. Остальные существующие контролы (`.site-socials__link`, `.site-footer__top-btn`/`__menu-btn` и т.п.) на
  `.btn` задним числом не переводятся — они лежат в своих файлах
  (`site-chrome.css`, `header.css`, `footer.css`) и служат эталоном/
  документацией типов в `styles/buttons.css`; трогать их не нужно.

Полный список типов, их состояний и примеры разметки — в комментарии
наверху `styles/buttons.css`.

Перед тем как добавить кнопку в любом месте сайта (Главная, `projects/`,
`works/`, любая новая страница) — сначала открой `styles/buttons.css` и
собери кнопку из существующих классов. Если действительно не хватает
типа — расширь этот файл новым `.btn--fill-*`/`.btn--icon-*`, а не пиши
кастомный CSS рядом со страницей.

Это проверяется автоматически: `node scripts/check-design-system.js`
запускается перед деплоем (`.github/workflows/deploy-hostinger.yml`) и
падает, если найден `<button>`/`[role="button"]` без `.btn` вне списка
уже существующих эталонных кнопок (см. `BUTTON_LEGACY_PREFIXES` в
скрипте) — сборка красная, пока не исправлено.

## Шрифты — только из дизайн-системы

Для ВСЕГО сайта: у подзаголовка из одного предложения завершающая точка не ставится.
У нескольких предложений пунктуация сохраняется; `?`, `!`, многоточия и точки
сокращений/инициалов остаются. Новые подзаголовки помечать `data-subtitle` с
существующей текстовой ролью ДС. Общий обработчик — `site/typography-rules.js`.

`styles/typography.css` — то же самое правило, что и для кнопок, только
для текста: единственный источник шрифтов на сайте, жёстко, без исключений.

- Заголовки — Playfair Display 400 (с засечками) на всех уровнях, включая H1 Главной
  (`.mood-title`): `.text-display-lg`/`.text-display`/`.text-h1`/
  `.text-h2`/`.text-h3` отличаются ТОЛЬКО размером
  (`font-size`), family/вес/трекинг/интерлиньяж/оптические оси —
  общие токены (`--font-family-heading`, `--letter-spacing-heading`,
  `--line-height-heading`). Новый уровень заголовка не изобретается —
  берётся ближайший существующий `.text-h*`.
- Обычный текст — один стиль на весь сайт, снят с подзаголовка Главной
  (`.mood-subtitle`): `.text-body`/`.text-body-lg`/`.text-body-sm`
  используют один и тот же `--font-size-text`/`--line-height-text`/
  `--letter-spacing-text`, отличаются только `max-width` (длина строки).
- Текст кнопок — один стиль на любой кнопке сайта, большой или
  маленькой, снят с кнопок Главной (`.mood-primary`): `.text-button` и
  шрифт `.btn` в `styles/buttons.css` читают те же токены
  (`--font-size-text`/`--letter-spacing-text`, полужирный).
- Свой `font-family`/размер/трекинг для текста в другом файле или в
  `<style>` страницы — не писать. Нужна роль текста — берётся
  существующий `.text-*` из `styles/typography.css`, а не создаётся
  bespoke стиль на месте.
- Проверяется тем же скриптом: `node scripts/check-design-system.js`
  падает на любом `font-family:`, заданном литералом (не `var(--font-family-*)`)
  вне файлов-исключений (`fonts.css`, `typography.css`, `site-chrome.css`
  и ещё пара устаревших — см. `FONT_EXEMPT_FILES` в скрипте).


## Баннер Главной — закреплённый компонент

`components/hero-mood/` — утверждённый светлый баннер с объёмными сферами.
Источник: `template.html`; в `index.html` копия между `component:hero-mood`.
Стили и поведение: `components/hero-mood/hero-layout.css`, `components/hero-mood/hero-viewport.js`, `components/hero-mood/hero-spheres.js`.

- Не менять баннер при задачах про другие части сайта, в том числе общими переопределениями.
- Баннер имеет два варианта: Главная со сферами, внутренние страницы с картинкой.
  Заголовок, подзаголовок, картинка и основное действие — контент страницы.
  Есть ссылка на прод — кнопка ведёт на прод; нет ссылки — прокручивает к содержимому.
  Не выравнивать тексты страниц под шаблон Главной. Контракт: `components/page-hero/README.md`.
- Проверка шаблона защищает каркас, а не тексты и параметры основной кнопки.
  `--sync` сохраняет текущий контент; CSS/JS баннера защищены точными хешами.
- Шаблон и `baseline.json` меняются только по явной просьбе изменить баннер.
- После разрешённой правки: `node scripts/hero-mood-component.js --sync`, визуальная проверка, обновление хешей изменённых файлов.
- Проверка: `node scripts/hero-mood-component.js` (также перед деплоем).
- Общая шапка и контакты: `components/site-chrome/site-chrome.css`, `components/site-chrome/site-chrome.js`.


## Нахлёст секций — единый механизм

- Секции с заливкой используют общий нахлёст из `components/page-motion/page-motion.js`
  и `components/page-motion/page-motion.css` на всех устройствах: `position: sticky` у
  предыдущего блока и один CSS-переход затухания при пересечении порога.
- Для новых секций кейса используется `.case-block--surface`, для коллекций
  проектов — `.project-slider--themed`. Скрипт сам собирает общую обёртку.
- Не добавлять отдельный скролл-движок для десктопа или мобильных и не
  пересчитывать `transform`/`opacity` секций на каждом событии скролла.
- Сохранять возврат при прокрутке вверх, навигацию к исходной позиции блока
  и отключение эффекта при `prefers-reduced-motion: reduce`.


## Палитра кейса

Цвета кейса подбираются под вайб проекта: токены `--case-surface`,
`--case-accent(-text)`, `--case-icon(-ink)`, `--case-icon-2(-ink)` задаются в
`:root` inline-стиля страницы кейса (описание — в начале
`components/case-blocks/case-blocks.css`). Без них кейс остаётся в нейтральной
гамме сайта. Кнопки палитру кейса не берут — они всегда из `styles/buttons.css`.

Обложка кейса одна на Главную и на страницу: файл в `projects/<…>/<кейс>/covers/`,
подключён в `pages/home/data/projects.js` и тем же файлом — первым кадром
`.case-cover__media` в `#summary` кейса (для видео — тот же `poster`).
Проверяет `node scripts/check-case-covers.js` (входит в `npm run check`).

## Лента проектов Главной и теги

`components/project-feed/` — лента опубликованных кейсов на Главной (без
горизонтального скролла): заголовок «Интерфейсы со смыслом» в стиле H2, переключатель
платформы Все/Mobile/Web по центру и сетка обложек (две колонки, на телефоне одна).
Данные и теги — `pages/home/data/projects.js`.

- На Главную попадают только описанные кейсы. Новый кейс — запись в
  `projects.js`, а не отдельная страница раздела.
- У проекта не больше четырёх тегов, по одному из групп: компания, аудитория,
  сфера, продукт. Платформа — отдельное поле `platforms`, выбирается переключателем.
- Теги под обложкой пока некликабельные подписи (`.feed-card__tag`, не `.btn`);
  если не помещаются — строка прокручивается (`components/chip-scroller/`).
- Кликабельна только обложка; название и описание — текст. Наведение на обложку
  уменьшает рамку (`--wg-hover-scale`), как кликабельные картинки в кейсах.
- Выбор платформы живёт в адресе (`/?platform=web#works-gallery`); хлебных
  крошек на Главной нет. На кейсах крошки обязательны на всех разрешениях:
  `Проекты › Кейс` (`components/breadcrumbs/`).
- Обложки: `--project-card-radius` (8px) и `--project-cover-border` из
  `styles/card-tokens.css` — та же лёгкая обводка, что у дропдаунов.
- Страницы разделов (`projects/<раздел>/`) и незаполненные заготовки кейсов
  скрыты временными редиректами в корневом `.htaccess`; файлы оставлены на
  будущее. Они по-прежнему используют `components/work-gallery/`.
