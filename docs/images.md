# Ресурсы сайта

Обложки коллекций Главной находятся в `pages/home/assets/avito/` и
`pages/home/assets/ozon/`, в формате WebP. Баннер и обложка раздела — в
`projects/<раздел>/assets/`. Общие иконки находятся в `components/icons/`,
аватар, логотип и favicon — в `components/site-brand/`. Корневого `assets/` нет.
Варианты `640`, `1280`, `1920` используются через `srcset` и прямые ссылки;
`original` нужен отдельным карточкам. Это рабочие размеры, не случайные копии.
Подключения и выбор вариантов: `pages/home/data/avito.js`, `ozon.js`
и HTML разделов в `projects/`.

Неподключённые PNG-папки `covers avito/` и `covers ozon/` убраны из проекта.
Исходники сохранены отдельным проверенным ZIP-архивом в локальном каталоге
`~/Documents/my-website-source-assets/`: часть имеет большее разрешение,
а Ozon 8 — исходный скриншот интерфейса, отличный от обложки с ноутбуком.
Архив не является зависимостью сайта и не участвует в деплое.

Новые исходники хранить вне публикуемого дерева. В проект добавлять готовые
ресурсы, которые нужны страницам, сохраняя существующие пути и варианты `srcset`.

## Автоматический импорт PNG

При `npm run dev` новый PNG автоматически превращается в WebP рядом с исходником;
после успешной конвертации обновляются локальные ссылки в HTML/CSS/JS/JSON,
а PNG удаляется. Размеры, прозрачность и пиксели сохраняются (lossless WebP).
Готовые WebP повторно не пережимаются. При копировании файла процесс ждёт
окончания записи. Ссылки, добавленные после конвертации, тоже обновляются.

Отдельный наблюдатель: `npm run images:watch`; разовая подготовка:
`npm run images:prepare`. Нужен `cwebp` из пакета `webp`.
Автокоммит вызывает ту же подготовку, а CI обязательно выполняет её перед
проверками и деплоем — PNG, загруженный прямо в репозиторий, на сайт попадёт
уже как WebP. CI не создаёт обратный коммит: преобразование выполняется в
копии для публикации. Для локального просмотра с автоимпортом нужен `npm run dev`.

Существующий WebP с другим содержимым не перезаписывается: новый PNG нужно
назвать иначе. Повреждённые файлы, APNG и 16-битные PNG сохраняются с сообщением
об ошибке; публикация останавливается, чтобы не потерять анимацию или данные.
При ошибке кодирования исходник не удаляется.
