# Админка

Локальная визуальная админка сайта. Работает только на своём компьютере,
правит файлы репозитория и публикует их обычным путём: коммит и push в `main`,
дальше деплой GitHub Actions.

```
npm install        # один раз: parse5 для правки HTML
npm run admin      # → http://localhost:8010/dev/admin/
```

Нужен `cwebp`, как и для `npm run dev` (`brew install webp`).

## Разделы

**Главная** — сетка ленты как на десктопе (4 колонки).

- Перетащите обложку в свободную клетку или на плитку того же размера, и они поменяются местами.
- Размер плитки: обычная 5:6 (файл 1500 × 1800) или крупная 2×2 3:4 (1800 × 2400).
  Если пропорции файла не совпадают с плиткой, админка предупредит.
- Порядок на телефоне повторяет чтение десктопной сетки: слева направо, сверху вниз.
- «+ Новый проект» или двойной клик по свободной клетке создают проект: обложка
  ленты, необязательное видео, сразу страница кейса. Новый проект стоит в ленте
  со «Скоро появится», пока не снята галочка в его карточке. Снять её можно
  только когда на странице есть первый кадр.

**Страницы** — визуальный редактор страниц из `projects/`.

- Клик выбирает текст, картинку, элемент или блок. ⌥-клик выбирает блок целиком.
  Справа появляются действия, подсказки и цепочка вложенности.
- Двойной клик по тексту включает правку на месте. Enter сохраняет, Shift+Enter
  переносит строку, Esc отменяет, ⌘B делает жирным.
- Картинка: «Заменить…» или файл, перетащенный на неё из Finder. Подсказка
  считает размер места на экране и нужную ширину файла (×2 для ретины на
  десктопе, ×3 на телефоне) и показывает, хватает ли текущего файла.
  `width`/`height` в разметке обновляются сами.
- Блоки: ↑/↓, перетаскивание в «Структуре страницы», дублирование, удаление.
  Оглавление кейса (`.work-toc`) пересобирается само.
- «+ Новый блок» открывает библиотеку раскладок `components/case-grid`
  (`dev/admin/blocks.js`). Серые поля `.cg-stub` — места под кадры: размер подписан
  внутри, файл загружается кликом. Текст со знаком ✎ — заготовка.
- Первый кадр кейса (`#summary`) и обложка в `pages/home/data/projects.js`
  обновляются вместе: это требование `scripts/check-case-covers.js`.
- Палитра кейса (`--case-*`), заголовок вкладки и описание.

**Ссылки и файлы**

- Резюме PDF заменяет `cv.pdf` и увеличивает `?v=` во всех ссылках.
- Пункты окна «Связаться» и меню разделов (`components/site-chrome/site-chrome.js`).

**Публикация**

- Список изменённых файлов.
- Предупреждения: пустые места под кадры, заготовки ✎, опубликованный кейс,
  который `.htaccess` перенаправляет на Главную (исправляется кнопкой).
- Неиспользуемые файлы: загруженные в админке удаляются по умолчанию, давние — по отметке.
- «Проверить и опубликовать»: PNG → WebP, `npm run check`, коммит, `git push`.
  Если проверка не прошла, ничего не отправляется.

«Отменить» (⌘Z) откатывает последние действия, пока сервер запущен.
После публикации история очищается — дальше помогает Git.

## Как устроено

| Файл | Назначение |
| --- | --- |
| `scripts/admin/server.js` | Локальный сервер на 127.0.0.1: раздаёт сайт, API правок, загрузки, публикация |
| `scripts/admin/html-source.js` | Правка HTML по позициям в исходнике (parse5): меняется только затронутое место |
| `scripts/admin/feed-data.js` | Чтение и запись `pages/home/data/projects.js` в его же формате |
| `scripts/admin/admin.test.js` | `npm run admin:test` — проверки на настоящих файлах сайта |
| `dev/admin/` | Интерфейс; `editor.js` встраивается в страницу при `?admin-edit` |

- Страница открывается в iframe с атрибутами `data-admin-id` — номерами
  элементов в исходнике. Номер действителен для одной версии файла: если файл
  поменялся снаружи, правка отклоняется и страница перезагружается.
- Загрузки: `covers/` — для первого кадра и обложек ленты, `media/<id-блока>/` —
  для содержимого. Имя файла — kebab-case латиницей с размером (`name-2880x1600.webp`),
  существующие файлы не перезаписываются. PNG сразу конвертируется
  `scripts/prepare-images.js`.
- Место плитки в ленте хранится в поле `place: { c, r, big }` проекта.
  Без него `components/project-feed/project-feed.js` берёт место из набора `PATTERN`.
- `dev/` и `scripts/` не публикуются (исключены в деплое), проверка ДС их не сканирует.
