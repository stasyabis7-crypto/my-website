# Автотесты и мониторинг сайта

`npm run check` проверяет компоненты, ДС, ресурсы, типографику и оба языка.
`npm run admin:test` проверяет редактор контента.

`npm run test:browser` запускает Playwright в Chromium на ширинах компьютера
и телефона. Проверяются Главная, «Обо мне», статьи, Playground, CRM и подписка:
HTTP-ошибки, необработанные ошибки JavaScript, загрузка изображений при прокрутке,
горизонтальный скролл, переход в кейс и возврат назад, переключатель языка,
блокировка localStorage, старые ссылки и чистые адреса. Отдельные сценарии
задерживают картинку без блокировки страницы и проверяют запуск видео
при приближении к экрану и остановку после прокрутки.
Индикатор каждой картинки проверяется отдельно: центр фрейма, отсутствие текста,
общая анимация с загрузчиком страницы, исчезновение после загрузки или ошибки
и сохранение размеров блока.

Тестовый сервер `scripts/test-server.js` запускает настоящий Apache с `.htaccess`
на `127.0.0.1:8123`. Проверяются серверные 301/302 и 404, внутренний DirectoryIndex,
cookie GeoIP и приватное кэширование HTML. Сервер делает временную копию
публичных файлов и удаляет её после завершения. Страна фикстуры — US;
выбор русского для стран СНГ и приоритет ручного выбора дополнительно покрыты
`scripts/language.test.js` и браузерным сценарием страны KZ.

## Скорость

`npm run test:performance` проверяет холодную загрузку и прокрутку каждой
страницы. Компьютер: 20 Мбит/с, задержка 20 мс. Телефон: 6 Мбит/с, задержка
80 мс, процессор замедлен в 4 раза. Кэш браузера отключён.

Бюджеты — `scripts/browser/performance-budgets.json`:

| Метрика | Компьютер | Телефон |
| --- | --- | --- |
| Ответ сервера (TTFB) | 1,2 с | 1,8 с |
| Первый контент (FCP) | 2,5 с | 3,5 с |
| Крупнейший контент (LCP) | 4 с | 5 с |
| Готовность страницы без загрузочной шторки | 5 с | 8 с |
| Блокировка основного потока при загрузке | 500 мс | 1000 мс |
| Блокировка при прокрутке | 300 мс | 600 мс |
| Сдвиги раскладки (CLS) | 0,1 | 0,1 |
| Начальные ресурсы | 8 МиБ | 8 МиБ |

У Playground отдельный бюджет: 16 МиБ на компьютере, где одновременно видны
несколько видеороликов, и LCP до 6 с на телефоне. Порог готовности интерфейса
остаётся общим. Это ограничения регрессии текущего видеокаталога, а не оценка
«хорошо» Core Web Vitals; для LCP ориентир хорошего результата — 2,5 с.

Для CLS берётся наибольшее окно до пяти секунд с паузами до секунды.
Блокировка — сумма превышений 50 мс у длинных задач. В отчёте сохраняются
измерения и источники сдвигов. Сторонняя аналитика заглушена: её доступность
не определяет исправность сайта. Внешние публикации и контактные сервисы
не обходятся автоматически. Тесты ловят регрессии в заданных условиях;
скорость у конкретного посетителя также зависит от устройства и сети.

Измерение LCP ждёт изображения первого экрана и наблюдает загрузку минимум
пять секунд; ранний текст не должен скрывать позднее появление большой картинки.
Шторка освобождает страницу после DOM и шрифтов (ожидание шрифтов ограничено
двумя секундами), не ждёт всех медиа. Видео кейсов и Playground подключает
`components/responsive-video/lazy-video.js` при приближении к экрану; вне экрана
и в фоновой вкладке они стоят на паузе. Reduced motion сохраняет постер или
первый кадр ролика без автопроигрывания.

## Автоматический запуск

`Deploy to Hostinger` запускается при PR, push в main и вручную. Перед отправкой
на хостинг выполняются подготовка PNG, статические проверки, тесты админки,
создание CDN-хешей и браузерные тесты. Ошибка останавливает публикацию.
После отправки проверяются действующий сайт и HTTP-кэширование.

`Monitor published site` запускается каждые 30 минут (в 17 и 47 минут часа,
UTC) и вручную из вкладки Actions репозитория. Проверяет
`https://stasyabis.com` с теми же бюджетами. Расписание начинает работать
после попадания workflow в основную ветку. GitHub может задерживать расписание:
это периодическая проверка, а не точный таймер доступности.

Почтовая отправка не подключена по просьбе владельца. Неудачный запуск виден
во вкладке Actions. Артефакты `site-browser-report`, `published-site-report`
и `site-monitor-report` хранятся 14 дней: HTML-отчёт, измерения JSON, скриншоты
и трассировки ошибок. Локально — `.artifacts/browser/`; они не попадают в Git
или на хостинг. Для просмотра: `npx playwright show-report .artifacts/browser/report`.

Проверка действующего сайта вручную:

```sh
SITE_URL=https://stasyabis.com npm run test:browser
```

Проверка CDN-хешей в одноразовой копии, без изменения рабочих файлов:

```sh
TEST_VERSION_ASSETS=1 npm run test:browser
```

Документация: [Playwright](https://playwright.dev/docs/test-webserver),
[расписание GitHub Actions](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule).

## Чистые адреса

Внутренние ссылки ведут на `/`, `/about/`, `/projects/articles/` и каталоги
кейсов. Apache перенаправляет `/index.html` и `/about/index.html` на каталог;
`/about.html` поддерживается как совместимый адрес существующего каталога.
Якоря и старый языковой параметр сохраняются при серверном редиректе;
языковой скрипт затем убирает `lang` через History API.
Параметры версий у CSS/JS остаются служебными адресами ресурсов; видимые адреса
страниц их не получают. Файлы и видео не переименовываются в страницы.
