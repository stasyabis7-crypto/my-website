# Портфолио

Статический сайт: HTML, CSS и JavaScript, без сборки приложения.
Правила изменений — [AGENTS.md](AGENTS.md), карта дизайн-системы и поведения —
[docs/design-system.md](docs/design-system.md).

## Структура

| Путь | Назначение |
| --- | --- |
| `index.html` | Главная; статические копии закреплённых шаблонов |
| `projects/` | Разделы, кейсы, заготовки и совместимые старые адреса |
| `pages/home/` | Данные и подборки обложек Главной; входная страница — корневой `index.html` |
| `components/` | Переиспользуемые компоненты: CSS, JS, шаблоны и README рядом |
| `styles/` | Основы ДС: типографика, кнопки, цвета, отступы, контейнер |
| `site/` | Общие службы: тема, аналитика, типографические правила, тактильный отклик |
| `components/icons/`, `components/site-brand/` | Иконки ДС и ресурсы айдентики: логотип, аватар, favicon |
| `dev/` | Локальные стенды: `previews/` и `grid/`; не публикуются |
| `docs/` | Дизайн-система, дизайн, аналитика и инструкции |
| `scripts/` | Проверки, синхронизация шаблонов, подготовка медиа и CDN |
| `api/.htaccess` | Настройка каталога API |

## Локальная работа

Один раз установить `npm install` и WebP-кодировщик (`brew install webp` на macOS,
`sudo apt-get install webp` на Linux). Из корня: `npm run dev`, затем открыть
`http://localhost:8000/`. Этот режим запускает сервер и автоматический импорт PNG.
Стенд типографики: `http://localhost:8000/dev/previews/`.

`npm run check` запускает проверки компонентов, жестов галереи, ДС и локальных
ссылок и конвертера изображений. Нужны Node.js, npm и `cwebp`.
Необязательный `npm run auto-commit` также подготавливает изображения перед
коммитом; отправка отключена по умолчанию — см. [инструкцию](docs/auto-commit.md).

Деплой выполняется GitHub Actions при push в `main`: сначала PNG преобразуются
в WebP и обновляются ссылки, затем выполняется `npm run check`.
`version-gallery-assets.js` запускается только в копии для деплоя: он создаёт
имена с хешами и переписывает HTML. В рабочем дереве его запускать не нужно.

## Перед изменением компонента

1. Найти его источник в [карте ДС](docs/design-system.md); контент менять в данных или HTML.
2. Прочитать README компонента. Не переносить его поведение на новую страницу копированием JS.
3. Выполнить `npm run check`. Хеши закреплённых компонентов не обновлять ради зелёной проверки.
4. При изменениях интерфейса проверить затронутые страницы на мобильной и десктопной ширине,
   клавиатуру и `prefers-reduced-motion`. Статические проверки этого не заменяют.

Неподключённые страницы проектов могут быть заготовками, а старые адреса —
внешними ссылками. Их сохраняем. Историю удалённых устаревших реализаций хранит Git.
