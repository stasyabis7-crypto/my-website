# Баннер-сад (Hero Garden)

Закреплён текущий баннер Главной. Это статический HTML-компонент:
`template.html` — источник разметки, `index.html` содержит её копию
между маркерами `component:hero-garden`. Так баннер доступен и без JS.
Синхронизация: `node scripts/hero-garden-component.js --sync`.

Стили и интерактивность остаются в `styles/hero-garden.css` и
`styles/hero-garden.js`, чтобы сохранить пути и существующее поведение.
`baseline.json` фиксирует SHA-256 шаблона, CSS, JS, зон и каталога цветов.
Проверка `node scripts/hero-garden-component.js` запускается перед деплоем.
Эталон включает локальное состояние CSS на момент выделения компонента.

Менять эти файлы и эталон можно только по явной просьбе изменить баннер.
После такой правки синхронизировать HTML, проверить баннер на мобильном
и десктопном экранах, затем обновить SHA-256 изменённых файлов в эталоне.
При работе над другими частями сайта не менять эталон и не переопределять
баннер через внешние стили или скрипты.

Общие зависимости: дизайн-система (`typography.css`, `buttons.css`,
`fonts.css`, `icons.css`), тема, размеры страницы и хедера, GSAP,
`assets/garden/`, `api/flowers.php`. Загрузчик ждёт `window.__gardenReady`.
Хеш-проверка не является визуальным тестом: изменения общих зависимостей
требуют проверки, что баннер сохранил вид и поведение.

Для будущей обложки проекта закреплён именно лейаут: композиция, размеры,
отступы, скругления, расположение контента и адаптивное поведение.
Цветочки из БД, счётчики и посадка остаются только на Главной. Обложка
не должна подключать `hero-garden.js`, запрашивать `api/flowers.php`
или ждать `window.__gardenReady`.

Будущая обложка проекта пока не реализована. При её добавлении использовать
лейаут как основу и выделить отдельный вариант, сохраняя Главную.
Текущая версия рассчитана на один баннер на Главной: в ней фиксированные
ID, пути от корня страницы и интерактивный сад. Для вложенной страницы
потребуется явно адаптировать пути, содержимое и поведение.
